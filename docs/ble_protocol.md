# BLE 通信の決まり（お守り端末 ⇔ PC）案

PC直結の中継スクリプト `scripts/ble_gateway.py` と、お守り端末（M5StickS3）のプログラムで、この決まりをそろえる。
**仮の案**なので、端末担当と相談して変えてよい。変えたときは、このファイルと `scripts/ble_gateway.py` の先頭の定数を両方直すこと。

## 全体の流れ

```
お守り端末（M5StickS3） ──BLE──> PC（ble_gateway.py） ──HTTP──> サーバー（/api/sync） ──> DB ──> 管理者用サイト
```

- 端末は歩数を **時間帯ごと**（例: 10分ごと）に区切って、本体に記録しておく。
- PC が近くに来た端末と接続し、まだ送っていない記録をまとめて受け取る。
- サーバーに保存できたら、PC が端末に「ここまで保存した」（ACK）と伝える。端末はそこで初めて記録を消す。
  → 途中で切れても記録はなくならない。同じ記録が2回届いても、サーバーが重複として数えない。

## 端末が名乗る名前（アドバタイズ）

- 名前（Local Name）: `omamori-01`、`omamori-02` … （この名前がそのまま端末 ID になる）
- 使える文字: 英数字と `_ - : .`、64文字まで
- 名前はアドバタイズに、下のサービス UUID はスキャン応答に入れる（両方をアドバタイズに入れると 31 バイトを超えるため）
- PC は名前の始まり `omamori-` で探す

## サービスとキャラクタリスティック

| 名前 | UUID | 向き | 種類 |
|---|---|---|---|
| サービス | `9a680eec-1bbc-4a41-8d1a-5825119870c1` | | |
| DATA | `49501394-5798-42c9-a6da-da5ca2b387b3` | 端末 → PC | Notify |
| CTRL | `33eeafb4-bd92-45e4-a92d-925ebcc8835d` | PC → 端末 | Write（応答あり） |

数値はすべて **リトルエンディアン**。時刻は **UNIX 時間（1970-01-01 00:00 UTC からの秒数）**。

## CTRL（PC → 端末の命令）

| 命令 | バイト列 | 意味 |
|---|---|---|
| 時計合わせ | `0x01` + uint32 今の時刻 | 端末の時計をこの時刻に合わせる |
| 送って | `0x02` | まだ ACK されていない記録を、DATA で古い順に送る |
| ACK | `0x03` + uint32 時刻 T | サーバーに保存できた。measured_at が T 以下の記録は消してよい |

## DATA（端末 → PC の通知）

1回の通知 = `件数 n（uint8）` ＋ `記録 × n`

記録1件 = 6バイト:

| 位置 | 型 | 内容 |
|---|---|---|
| 0〜3 | uint32 | measured_at（その時間帯の**終わり**の時刻、UNIX 秒） |
| 4〜5 | uint16 | その時間帯に歩いた歩数（**累計ではない**） |

- **件数 0 の通知（1バイト `0x00`）が「送り終わり」の合図。** 記録が1件もないときも、これだけは送る。
- 「送って」を受けたとき、今の時間帯の途中までの歩数も区切って記録にし、一緒に送る（measured_at は送った時刻）。
  管理者用サイトに、同期した時点までの歩数が出るようにするため。
- 時計が合う前の記録（時刻がわからないもの）は送らない。
- 1回の通知に入れられる件数は MTU で決まる: `n ≦ (MTU − 3 − 1) ÷ 6`。
  MTU 23（初期値）なら 3件、MTU 247 なら 40件。
- 長さが合わない通知が来たら、PC は同期を失敗として記録し、ACK は送らない。

例: 2026-10-16 09:00（日本時間）までの10分に 120歩
→ measured_at = 1792108800（= 2026-10-16 00:00 UTC）
→ 通知 `01 00 69 D1 6A 78 00` の後に `00`

## 手順

```
PC                                   端末
 |-- スキャン（名前が omamori- で始まるもの）
 |-- 接続 -------------------------->|
 |-- DATA の通知を有効にする --------->|
 |-- CTRL: 0x01 + 今の時刻 ---------->|  時計を合わせる
 |-- CTRL: 0x02 --------------------->|
 |<-------------- DATA: n件 ----------|  （何回かに分けて）
 |<-------------- DATA: 0件 ----------|  送り終わり
 |-- サーバーへ POST /api/sync
 |-- CTRL: 0x03 + 最後の時刻 --------->|  サーバーに保存できたときだけ
 |-- 切断
```

- PC 側の待ち時間: 接続 15秒、受け取り 30秒（`--connect-timeout`、`--transfer-timeout` で変えられる）
- 失敗したとき（見つからない・接続できない・時間切れ）も、サーバーの同期記録に「失敗」として残す（BLE の検証用）

## 端末側の実装

`firmware/omamori_m5/`（Arduino・M5Unified・NimBLE-Arduino 2.x）。使い方は [firmware/README.md](../firmware/README.md)。

## 端末側で気をつけること（端末担当と相談したい点）

1. **時計**: 電源を入れた直後は時計が合っていない。最初の時計合わせ（`0x01`）が来るまでの記録をどう扱うか。
   - サーバーは 2024-01-01 より前と、今より10分以上先の時刻の記録を保存しない（「時刻エラー」として数える）。
2. **記録の容量**: PC と何日も接続できなかったときに、何件まで持っておけるか。
3. **区切りの長さ**: 10分ごとを想定。短くすると件数が増え、同期の時間が長くなる。
4. **電池**: アドバタイズの間隔と、PC の同期の間隔（初期値 5分）の兼ね合い。
