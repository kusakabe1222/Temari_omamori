## 3. 注意が必要な処理

### データ・ファイルを消す処理

| どこ | 何が消えるか | 守り |
|---|---|---|
| `scripts/seed.py --reset` | 利用者・端末・歩数・同期記録・LINE 送信記録の**全部**（設定は残る） | 消える件数を表示し、`yes` と入力したときだけ消す |
| 画面「登録・編集」→ 利用者の削除 | その利用者と、**その人の歩数の記録すべて** | 確認ダイアログ。サーバー側でも `confirm=yes` がないと消さない |
| 画面「登録・編集」→ 端末の削除 | 端末の登録だけ | 歩数の記録がある端末は消せない。確認ダイアログあり |

- ファイルを消す処理はない。DB ファイル（`data/omamori.db`）は、なければ作るだけ。

### 外部との通信

| どこ | 相手 | いつ |
|---|---|---|
| `app/line_notify.py` | `https://api.line.me`（LINE） | `.env` に LINE の値があり、画面のボタンを押したとき／自動送信をオンにして過負荷になったとき（1人1日1回まで、失敗は3回まで） |
| `scripts/fake_tablet.py`, `scripts/ble_gateway.py` | このサーバー（初期値 `http://127.0.0.1:8000`） | 実行したとき |
| `scripts/ble_gateway.py` | 近くの BLE 機器 | スキャンは名前を読むだけ。接続は名前が `omamori-` で始まるものだけ |
| 準備の作業（生成AIが実行済み） | PyPI（`pip install`）、npm 公式レジストリ（Chart.js） | 2026-10-09 に1回。サーバーを動かしている間は通信しない |

- サーバーは初期設定で `127.0.0.1`（この PC）からしか開けない。
- 画面は CDN を使わない（Chart.js は `app/static/vendor/` に置いた）。FastAPI の `/docs` は CDN を読むので止めてある。

### パスワード・キー・個人情報

- パスワード・API キー・LINE のトークンは `.env` にだけ置く（`.gitignore` 済み）。コードには書いていない。
- パスワードと API キーの比較は `hmac.compare_digest`（時間で中身を推測されないように）。
- LINE に送るのはニックネームと歩数だけ。ダミーデータもニックネームだけ。
- ログインの試行回数の制限はない（学内デモ用のため）。CSRF 対策はクッキーの `SameSite=Lax` のみ。

### 画像

- 生成AIで作った画像は使っていない。アイコンは使わず文字だけ。

## 4. 最初の設計から変えた点・足した点

| 点 | 変えたこと | 理由 |
|---|---|---|
| データの流れ | タブレットの代わりに **PC 直結**（`scripts/ble_gateway.py`）を追加 | 依頼者の希望。サーバーの入口は同じなので、タブレットにも戻せる |
| `step_records` | `user_id` を追加（受信したときの持ち主） | 端末を別の人に渡しても、過去の歩数が新しい人のものにならないように |
| `sync_logs` | `source`, `status`, `inserted_count`, `skipped_count`, `note`, `error`, `received_at` を追加 | BLE 検証で、失敗した同期・距離のメモ・送信元（本物／にせ／ダミー）を区別するため |
| `line_logs` | 新しく追加 | LINE に送った記録と、同じアラートを何度も送らないため |
| API の認証 | `/api/sync` は `X-API-Key` ヘッダーが必要 | ログインのパスワードは画面用なので、中継用に別のキーを用意 |
| 未登録の端末 | 自動で「持ち主なし」として登録し、データは保存 | デモ中にデータが消えないように |
| 同期記録の画面 | `/sync-logs` を追加 | BLE 検証（距離・成功率・同期時間）を画面でも見られるように |
| 未同期アラート | 追加（初期値 24時間） | 電池切れや付け忘れに気づけるように |

## 5. 仮で決めたこと（チーム・施設・端末担当と確認が必要）

| 点 | 仮の決め方 | 確認する相手 |
|---|---|---|
| `steps` の意味 | その時間帯に歩いた歩数（累計ではない）。日別は日本時間の日付ごとの合計 | 端末担当 |
| 過負荷アラート | 今日の歩数が目標の **150%以上**（設定画面で変更可） | チーム・施設 |
| 未同期アラート | **24時間**データが届かない（0 で止める） | チーム・施設 |
| 端末の時計 | 2024年より前・今より10分以上先の記録は保存しない。PC が同期のたびに時計を合わせる | 端末担当 |
| BLE の決まり | `docs/ble_protocol.md` の案（10分ごとの記録、ACK を受けてから端末が消す） | 端末担当 |
| 利用者の削除 | その人の歩数も消す | チーム（研究データとして残す必要があるか） |
| 個人ページのグラフ | 目標の線に加え、過負荷の目安の線も表示 | チーム |

- このメモの「注意が必要な処理」に書いたもの以外に、削除・外部通信がないことを確かめた（`DELETE`, `urlopen`, `requests` などを検索）。
- テンプレートは自動でエスケープされる設定（Starlette の `select_autoescape`）であることを確かめた。
  削除の確認文はニックネームを含むので、`onsubmit` の中に埋め込まず `data-confirm` 属性から読む形にした（スクリプトが入り込まないように）。
- 直したところ: ダミーデータの「過負荷の例」が時刻によってはしきい値ぎりぎりになるので、多めにした。
  BLE の決まりの例のバイト列の計算違いを直した。

### 実行してから直したところ（このメモの見直しのあとに変えた点）

| ファイル | 直したこと | 理由 |
