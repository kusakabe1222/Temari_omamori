# お守り端末（M5StickS3）のプログラム

お守り型歩数計の端末側のプログラムです（Arduino）。歩数を数えて本体に記録し、PC の中継スクリプト（`scripts/ble_gateway.py`）と BLE でやりとりします。

> **コンパイルは確認ずみ（2026-10-14）。実機での確認はまだです。**
> 確認した組み合わせ: ボード M5Stack 3.3.9（M5StickS3）、M5Unified 0.2.19、M5GFX 0.2.26、NimBLE-Arduino 2.5.0
> 生成AIが書いたコードなので、授業のルールどおり、書き込む前にチームでレビューしてください（`docs/review/2026-10-09_M5端末プログラム.md`）。
>
> **WiFi は使いません。** 最初から M5 に入っているプログラム（UIFlow など）で WiFi につながっていても、このプログラムを書き込むと置きかわります。

## できること

| 機能 | 内容 |
|---|---|
| 歩数を数える | 加速度センサーの上下の揺れの「山」を数える。手で振ったような揺れ（強すぎる・速く回る・横や前後の揺れ・リズムがそろわない）ははじく。間隔のそろった6歩が続いてから数え始める |
| 記録する | 10分ごとに区切って本体に保存（電源が切れても残る）。歩いていない時間帯は記録しない。最大 432 件 |
| PC と同期 | PC から接続されたら、時計を合わせてから、まだ送っていない記録を送る。PC がサーバーに保存できたら（ACK）記録を消す |
| 画面 | ボタンA: 今日の歩数・時刻・電池。ボタンB: 端末の情報（端末ID・未送信の件数・時計・通信・はじいた揺れの回数）。15秒で消える |

通信の決まりは [docs/ble_protocol.md](../docs/ble_protocol.md) です。

## ファイル

| ファイル | 中身 |
|---|---|
| `omamori_m5/omamori_m5.ino` | プログラム本体 |
| `omamori_m5/config.h` | 設定（**端末ID**、BLE の UUID、歩数の検出のしきい値、画面） |
| `omamori_m5/step_detector.h` | 歩数の検出（手で振った揺れをはじく）。M5 に頼らない部分だけをまとめてある |

## 準備（Arduino IDE 2。最初に1回）

1. **ボードの追加**: 「ファイル → 基本設定 → 追加のボードマネージャのURL」に次を入れる
   `https://static-cdn.m5stack.com/resource/arduino/package_m5stack_index.json`
2. **ボードのインストール**: 左の「ボードマネージャ」で **M5Stack** を探してインストール（3.3.9 で確認）
3. **ライブラリ**: 左の「ライブラリマネージャ」で次を入れる
   - **M5Unified**（M5GFX も一緒に入る）
   - **NimBLE-Arduino**（作者 h2zero）— **2.x**（1.x とは書き方が違うので動きません）
   - ライブラリマネージャでダウンロードに失敗するときは、[GitHub の NimBLE-Arduino](https://github.com/h2zero/NimBLE-Arduino/releases) から zip を落とし、
     「スケッチ → ライブラリをインクルード → .ZIP形式のライブラリをインストール」で入れる
     （中身を `ドキュメント\Arduino\libraries\NimBLE-Arduino` に置いても同じ）
4. **ボードを選ぶ**: 「ツール → ボード → M5Stack → **M5StickS3**」

## 書き込み（端末ごとに）

1. `omamori_m5/config.h` の `DEVICE_ID` を、端末ごとに変える（例: `omamori-01`、`omamori-02`）
   - 管理者用サイトの「登録・編集」で、同じ端末IDを登録して持ち主を決める
2. **データ通信ができる USB-C ケーブル**で PC につなぐ（充電専用のケーブルだと PC に見えない）
3. **書き込みモードにする**: 横のリセットボタンを**約2秒長押し**し、中の**緑の LED が点滅**したら離す
4. 「ツール → ポート」で、出てきた COM ポートを選ぶ
5. `omamori_m5/omamori_m5.ino` を開いて「書き込み」（→ ボタン）
6. 終わったら、横のリセットボタンを**1回押す**と再起動して動き出す。画面に「きょうの歩数」が出れば成功

横のリセットボタン: 1回押す＝電源オン／再起動、2回押す＝電源オフ、長押し＝書き込みモード（M5Stack 公式の説明による）

## 動作確認の手順

1. **シリアルモニタ**（115200）を開くと、`[ble] omamori-01 として名乗り始めました` と出る
2. しばらく歩くと、10分ごとに `[slot] 〇〇 歩を記録` と出る。画面のボタンAで今日の歩数が見られる
3. PC で、近くに見えるか確かめる（サーバーと同じ PC、プロジェクトのフォルダで）

```powershell
.\.venv\Scripts\python.exe scripts\ble_gateway.py --scan
```

`omamori-01  ← お守り端末` のように出れば OK。

4. サーバーを起動したまま、1回同期する

```powershell
.\.venv\Scripts\python.exe scripts\ble_gateway.py --once
```

PC に `受け取り 〇件 → 新規 〇件` と出て、端末のシリアルモニタに `[cmd] 時計を合わせました`、`[cmd] 〇 件送りました`、`[cmd] ACK: 〇 件消しました` と出れば OK。
管理者用サイトの一覧と「同期記録」にも出ます。

## 歩数の数え方（`step_detector.h`）

手で振っただけの揺れを数えないように、次の順で見分けています（2026-10-30 に変更）。

1. 加速度から重力の向きを求め、**上下の揺れ**の山を「1歩の候補」にする
2. **強すぎる揺れ**（重力を除いて 1.2g 超）か**速すぎる回転**（300度/秒 超）があったら「振っている」とみなし、**2秒は数えない**（それまでの候補も捨てる）
3. 1歩のあいだに、**横・前後の揺れが上下の2倍より大きい**ときは数えない
4. **間隔のそろった山が6回続いたら**、まとめて数え始める（ここで6歩ぶん入る）。歩いている途中でリズムが大きくくずれたら、また6回たしかめ直す

ボタンBの画面の「**はじいた揺れ**」に、歩いていないと判断した回数が出ます。

**見分けられないもの**: 上下にゆっくり、一定のリズムで、回さずに振ると、歩くのとほとんど同じ揺れになるので数えてしまいます（市販の歩数計も同じです）。
また、歩きはじめて5歩以内に止まったときは数えません。

## 歩数の数え方の調整（大事）

しきい値は仮の値です。お守りとして首から下げる・かばんに付けるなど、付け方で揺れ方が変わるので、実際に試して `config.h` を調整してください。

1. 端末を付けて、声に出して数えながら **100歩** 歩く
2. 画面の歩数の増え方と比べる
   - **少なく数える** → `STEP_HIGH_G` を下げる（例: 0.10 → 0.08）。`CONFIRM_TOLERANCE` を大きくする（例: 0.30 → 0.40）
   - **ゆっくり歩くと数えない** → `MAX_STEP_MS` を長くする（例: 2000 → 2500）
   - **歩いているのに「はじいた揺れ」が増える** → 下の「くわしく見る」で理由を見て、そのしきい値をゆるめる
     （振っている → `SHAKE_ACCEL_G`・`SHAKE_GYRO_DPS` を上げる、横・前後 → `SIDEWAYS_RATIO` を上げる）
3. 手で振って、歩数が増えないことも確かめる（増えるなら、上と逆にしきい値をきびしくする）
4. 付け方ごとに、結果を記録しておく（検証のレポートに使える）

**くわしく見る**: `config.h` の `#define STEP_DEBUG 0` を `1` にして書き込むと、シリアルモニタ（115200）に山ごとのようすが出ます。

```
[step] 間隔 560ms  揺れ 0.41g  回転 62度/秒  横/上下 0.9  → 数えた（合計 54歩）
[step] 間隔 380ms  揺れ 2.30g  回転 640度/秒  横/上下 3.1  → はじいた: 振っている（合計 54歩）
```

調整が終わったら `0` に戻してください。

## わかっている制限・相談したい点

- **電池**: BLE で名乗り続け、加速度を 1秒に50回読むので、250mAh の電池では長く持たない見込み。名乗る間隔を長くする、眠らせるなどの工夫は、実機で電池の減り方を測ってから
- **時計**: 電源を入れた直後は時計が合っていない。PC と1回同期すると合う。それまでの記録は「起動してからの秒」で持ち、同期したときに本当の時刻に直す。時計が合う前に電源が切れると、その間の記録は時刻がわからないので捨てる（RTC がある場合は電源を入れ直しても時刻が残る）
- **安全**: BLE はペアリングなしでつながる。近くの人が同じ手順で接続すると、記録を読んだり、ACK を送って消したりできる（試作のため。ACK は「その接続で送った分」までしか受けつけないようにはしてある）
- **同期中**: 記録を送っている間（数百ミリ秒）は、歩数を数えるのが止まる
- **容量**: 432 件を超えると古いものから捨てる（ボタンBの画面に「捨てた記録」が出る）
- **日付の境目**: 23:50〜0:00 の歩数は、記録の時刻が 0:00 になるので、サーバーでは次の日として数えられる
